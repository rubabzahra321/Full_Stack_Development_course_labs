# UniAccess — University API Access Management System

FSD Lab 07 | Full Stack Development | AJAX + Node.js + Express + MySQL

## Features
- Professional responsive frontend with Dashboard, API Settings, and `/admin` panel.
- MySQL schema for students, teachers, academic marks, API keys, and API usage logs.
- Student API keys can only access the student linked to that key.
- Teacher API keys can view all students and marks.
- Admin API key protects every `/api/admin/*` endpoint.
- Add students and teachers from the admin panel; each new person is saved in MySQL and appears automatically in the API-key assignment dropdown.
- Generate keys, assign owners, configure/update request limits, inspect usage, and revoke keys.
- Generated API keys are stored as SHA-256 hashes; the raw key is shown only once.
- API usage is persisted in MySQL. Request limits are enforced server-side.
- AJAX requests use the `x-api-key` or `x-admin-key` HTTP header.

## Requirements
- Node.js LTS installed
- XAMPP (MySQL/MariaDB) or another local MySQL server
- VS Code (recommended)

## Step 1 — Create the database
1. Start **MySQL** in the XAMPP Control Panel.
2. Open `http://localhost/phpmyadmin`.
3. Click the **SQL** tab.
4. Open `schema.sql` from this project, copy all its SQL, paste it into the SQL tab, and click **Go**.
5. You should see the `university_api_db` database with `students`, `teachers`, `academic_marks`, `api_keys`, and `api_usage` tables. Sample student, teacher, and mark records are inserted.

The sample data is inserted idempotently for students, teachers, and marks, so rerunning the script will not duplicate the sample records.

## Step 2 — Configure the Node.js backend
1. Open the project folder `university-api-access` in VS Code.
2. Copy `.env.example` and name the copy `.env`.
3. The default values work with a typical XAMPP installation where MySQL is on port 3306 and `root` has a blank password. If yours is different, update `DB_PORT`, `DB_USER`, `DB_PASSWORD`, and `DB_NAME` in `.env`.
4. Open **Terminal → New Terminal** in VS Code. Make sure the terminal is in the folder containing `server.js` and `package.json`.
5. Run:

```powershell
npm install
```

6. Start the backend:

```powershell
npm start
```

7. Keep the terminal open. Visit `http://localhost:3000/api/health`; the response should report `"status":"ok"` and `"database":"connected"`.
8. Open `http://localhost:3000` for the frontend. The app is served by Express, so Apache is not required for this project (MySQL must be running).

## Step 3 — Open the admin panel
1. Visit `http://localhost:3000/admin`.
2. The default lab admin key is configured in `.env.example` as:

```text
university-admin-2026-secret
```

3. Paste it into the administrator authentication field and unlock the panel.
4. First, use **Add a student** or **Add a teacher** to register new people. Submit the form to save each person to MySQL. The new record will appear automatically in the key-assignment dropdown.
5. To issue a key, choose **Student** or **Teacher**, select the registered person, set a request limit (for example `5`), and click **Generate API key**. Existing sample records from `schema.sql` are also available. The database stores only its hash; the full key will not be shown again.
6. Copy the full key immediately. The database stores only its hash; the full key will not be shown again.
7. In the API key registry, choose **Edit limit** to update an active key or **Revoke** to disable it.
8. The recent activity table displays request events and HTTP response statuses.

For a real deployment, replace the default admin key with a long, private secret in `.env` and never publish it.

## Step 4 — Test student access
1. Go to **API settings**.
2. Choose **Student** and paste the student key generated by the administrator.
3. Click **Save and connect**.
4. The dashboard should show that student's profile and marks.
5. Try changing the browser URL or adding a student ID to the request URL: the student endpoint does not accept a student ID parameter; it obtains the student ID from the validated API key.
6. A student key calling `/api/teacher/students` receives HTTP `403 Forbidden`.

## Step 5 — Test teacher access
1. Go to **API settings**.
2. Choose **Teacher** and paste the generated teacher key.
3. Click **Save and connect**.
4. The dashboard should display the class overview and student list with marks.
5. A teacher key calling `/api/student/me` receives HTTP `403 Forbidden`.

## Step 6 — Test limits and revocation
- Generate a key with a small request limit such as `2`.
- Save it in API settings and load records repeatedly.
- After the limit is reached, the API returns HTTP `429 Too Many Requests`.
- Revoke the key from the admin panel; subsequent requests return HTTP `403 Forbidden`.
- Reload the admin activity table to see persisted usage events.

## API endpoint reference
All API keys are sent in HTTP headers, not query parameters.

| Method | Endpoint | Authentication | Purpose |
|---|---|---|---|
| GET | `/api/health` | None | Check server/database connection |
| GET | `/api/admin/overview` | `x-admin-key` | Summary counts |
| GET | `/api/admin/students` | `x-admin-key` | List students |
| GET | `/api/admin/teachers` | `x-admin-key` | List teachers |
| POST | `/api/admin/students` | `x-admin-key` | Add a student to MySQL |
| POST | `/api/admin/teachers` | `x-admin-key` | Add a teacher to MySQL |
| GET | `/api/admin/keys` | `x-admin-key` | View key registry |
| GET | `/api/admin/usage` | `x-admin-key` | View request logs |
| POST | `/api/admin/keys` | `x-admin-key` | Generate an assigned key |
| PATCH | `/api/admin/keys/:id/limit` | `x-admin-key` | Update request limit |
| PATCH | `/api/admin/keys/:id/revoke` | `x-admin-key` | Revoke a key |
| GET | `/api/student/me` | Student `x-api-key` | Get own profile and marks |
| GET | `/api/teacher/students` | Teacher `x-api-key` | Get all student records and marks |

### Generate-key request body

```json
{
  "role": "student",
  "ownerId": 1,
  "requestLimit": 5
}
```

### Update-limit request body

```json
{
  "requestLimit": 10
}
```

## HTTP status codes used
- `200 OK`: successful request
- `201 Created`: API key created
- `400 Bad Request`: invalid input
- `401 Unauthorized`: missing/invalid API key
- `403 Forbidden`: revoked key or role not permitted
- `404 Not Found`: record/key not found
- `429 Too Many Requests`: request limit exhausted
- `500 Internal Server Error`: unexpected server error

## Common problems
- **Database connection refused:** Start MySQL in XAMPP and check `DB_PORT`.
- **Unknown database:** Run `schema.sql` in phpMyAdmin and verify `DB_NAME` in `.env`.
- **Access denied for root:** Set the correct `DB_PASSWORD` in `.env`.
- **Cannot find module:** Run `npm install` in the project folder.
- **Port 3000 already in use:** Stop the other process or change `PORT` in `.env`.
- **Invalid API key:** Confirm the selected role matches the key's role and paste the complete key.
- **Request limit reached:** Increase the limit in the admin panel or generate a new key.
